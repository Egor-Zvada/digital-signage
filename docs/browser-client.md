# Клиент-экран: любой браузер

На клиентское устройство ничего из проекта устанавливать не требуется. Подходит
Raspberry Pi 5, мини-ПК, обычный компьютер, телевизор или медиаплеер, если на нём
есть современный Chromium/Chrome/Edge с поддержкой Service Worker и Cache Storage.

## Подключение

1. В панели сервера откройте **Экраны**.
2. Создайте экран и нажмите **Копировать ссылку** в его строке. Постоянный адрес
   доступен повторно в любое время, в том числе в настройках экрана.
3. Откройте эту ссылку в браузере.
4. Включите полноэкранный режим или настройте автоматический запуск браузера в
   режиме kiosk с этой ссылкой.

При каждом открытии ссылки и перезагрузке страницы показ начинается с первого
активного по расписанию элемента и затем повторяется по кругу. У каждого дисплея
своя очередь, не привязанная к общей временной шкале.

Пример для Chromium:

```bash
chromium --kiosk --no-first-run --disable-session-crashed-bubble \
  --autoplay-policy=no-user-gesture-required \
  'https://signage.vve.local/display/ID/TOKEN/'
```

На клиенте должен быть доверен CA, выпустивший сертификат `signage.vve.local`.
Предпочтительный вариант — существующий корпоративный Microsoft CA. Отдельный
Signage CA создаётся лишь при явном выборе установщика в среде без своей PKI;
публичный сертификат доверенного CA доступен по адресу
`http://signage.vve.local/signage-ca.crt`. Получать доверенный корневой сертификат
только по незащищённому HTTP без заранее проверенного отпечатка нельзя.

## Pi с основной RTSP-камерой

Передайте ссылку своей существующей программе на Pi: она открывает браузер на
нужное время, затем закрывает и возвращает камеру. Нового агента или скрипта из
проекта устанавливать не требуется. В следующий запуск очередь снова начнётся
сначала, даже если предыдущий сеанс закончился посреди видео.

В панели **Экраны → Настройки → Ожидаемое расписание подключений** задайте такой
же график, как у программы Pi. Сервер использует его для отображения плановых
пауз и времени следующего запуска; самостоятельно браузер не открывает и не закрывает.

Пример: **60 минут**, **10 минут**, рабочее время **09:00–18:00** означает показ
09:00–09:10, 10:00–10:10 и далее до 17:00–17:10. Для двух точных окон выберите
соответствующий режим и внесите:

```text
09:00-09:10
13:30-13:45
```

Дни недели без отметок означают каждый день. Время относится к часовому поясу канала.

## Передача файлов и автономная работа

По умолчанию **Автономный показ** выключен: полный плейлист не скачивается.
Текущий ролик воспроизводится прогрессивно через HTTP Range, остальные файлы
запрашиваются по мере необходимости. Это подходящий режим для периодических
сеансов браузера при доступном сервере. Полный цикл без сети в нём не гарантируется.

Для показа без связи включите **Автономный показ** в настройках экрана. Браузер
последовательно сохранит все локальные медиа опубликованного плейлиста, включая
полные видео. Это занимает место в профиле и расходует трафик. В **Экранах**
дождитесь **Готов к работе без сети**: там же отображаются число сохранённых файлов,
объём, ревизия и ошибки. У новой публикации прежняя полностью готовая программа
сохраняется до завершения подготовки следующей.

Живые внешние сайты требуют сеть. С ними статус будет **Частично готов**;
для автономного показа выберите **Снимок сайта**. Погода без сети остаётся последней
полученной, новые публикации и команды не приходят.

Ключ `--autoplay-policy=no-user-gesture-required` нужен для гарантированного звука
без клика. Если обычный браузер блокирует autoplay со звуком, плеер продолжает
показывать движущееся видео без звука. На экране клиента элементы управления и
кнопки не отображаются.

Для надёжности не используйте приватный режим браузера и не очищайте данные сайта
`signage.vve.local`. Для каждого физического экрана рекомендуется отдельный
профиль браузера. После смены профиля, очистки сайта или изменения используемой
ссылки локальную копию нужно готовить заново. Квотой и сохранностью данных
управляет сам браузер, поэтому автономный сценарий требуется проверить на устройстве.

Подробности, ограничения больших видео и настройка Microsoft CA описаны в
[полном русском руководстве](user-guide-ru.md).
